## 评审结论

当前已形成原生截图、编辑、导出、贴图和托盘的完整功能骨架，但状态模型、资源生命周期、UI动作和发布验收仍存在具体缺口。建议作为0.2.0预览阶段继续完善，先修正确性再扩功能。保留C++17 / Win32 / Direct2D / DirectWrite和可编辑对象模型，不引入第二套绘制后端。

ZoomIt用作函数级算法与资源处理参考；Snipaste用作界面入口、紧凑布局和操作节奏参考。不得把通用Win32 API相同或文档中的勾选当成成熟度证据。上游适配台账应记录实际函数、固定SHA、修改与回归。

## 改正项

### A01 · P0 · 选区与批注撤销状态分离

视角：架构；证据：静态确认。

源码位置：SnipClone/AnnotationOverlay/AnnotationOverlay.cpp:845；SnipClone/AnnotationOverlay/DrawStack.cpp:352；同文件:744

问题：调整选区调用 RemapForCrop，仅把图形列表写入撤销栈；Undo 恢复图形坐标，却不恢复 m_base.screenRect。仅改变右边/下边时 dx=dy=0，甚至没有选区撤销记录。

复现/核验：底图原点 X=100、文字局部 X=20；选区向右移10后局部 X=10，屏幕仍为120；撤销只恢复局部 X=20，屏幕变成130。此例由代码推导，未做桌面复现。

改正方案：将冻结图、选区、批注组成统一文档状态。批注保存冻结图坐标，裁切仅改变视口；选区与图形操作共同进入事务式历史。先用完整文档快照，后续有性能证据再改命令栈。

验收：画图→移动/缩放选区→撤销→重做，选区与图形屏幕位置一同恢复；四边调整均可撤销；缩小再扩大不丢对象。

### A02 · P0 · 合成失败可能被当作导出成功

视角：架构；证据：静态确认。

源码位置：SnipClone/AnnotationOverlay/AnnotationRenderer.cpp:593；同文件:630；同文件:641

问题：Compose 以 out=base 开始，WIC/渲染目标初始化失败直接返回底图；EndDraw 和 CopyPixels 未检查。DoCopy/DoSave/DoPin 只判断 Empty，可能成功输出不含批注的图片并关闭编辑窗口。

复现/核验：模拟 CreateWicBitmapRenderTarget、EndDraw 或 CopyPixels 失败，检查调用方是否仍关闭窗口、写出图片。失败注入为下一轮工作。

改正方案：返回明确的合成成功/失败结果并携带错误信息；检查全部关键 HRESULT。预览允许显示最后成功帧，最终导出失败保留编辑内容供重试；资源初始化采用完整成功标志和回滚。

验收：任一合成阶段失败均不得宣告输出成功；保留文档，可重试；PNG、剪贴板和贴图输出像素一致且不含界面装饰。

### A03 · P0 · 贴图关闭后的对象回收链断开

视角：架构；证据：静态确认。

源码位置：SnipClone/PinWindow/PinWindow.cpp:335；同文件:456；同文件:461；SnipClone/PinWindow/PinManager.cpp:43

问题：WM_DESTROY 清空 GWLP_USERDATA，StaticWndProc 在后续 WM_NCDESTROY 取不到 self，PinManager::OnNcDestroy 无法调用；关闭后的对象与图片仍保留在 m_pins，通常到 CloseAll 才回收。

复现/核验：连续创建并关闭大图片贴图，检查管理器数量和进程私有内存。这里只确认控制流问题，未测内存曲线。

改正方案：在 WM_NCDESTROY 最后解除窗口绑定，管理器统一负责对象销毁；明确 HWND 和 C++ 对象的所有者。选一种生命周期策略，避免窗口自删与容器所有权混用。

验收：关闭后活跃贴图数量立即下降，重复开关后内存趋于稳定；创建失败、退出和关闭全部均无重复释放。

### A04 · P1 · 输出目录被旧配置覆盖

视角：架构；证据：静态确认。

源码位置：SnipClone/main.cpp:394；SnipClone/AnnotationOverlay/AnnotationOverlay.cpp:719；SnipClone/PinWindow/PinWindow.cpp:210；SnipClone/Common/AppSettings.cpp:81

问题：批注与贴图保存会独立 Load/Save 新目录，main 的 g_settings 保留旧值，退出又 Save 覆盖。打开输出目录也使用旧副本。Save 不检查配置写入结果。

复现/核验：保存到新目录→正常退出→重启，目录可能退回旧值；启动后从托盘打开目录可能与最近保存位置不同。

改正方案：应用拥有一个设置服务，各窗口通过它更新字段；移除退出时旧快照覆盖，检查写入结果；增加值校验和热键冲突即时反馈。

验收：批注与贴图保存后，托盘目录、下次对话框和重启后的目录一致；写入失败提示且不宣称保存成功。

### A05 · P1 · 双击处理器缺少窗口类支持

视角：交互；证据：静态确认。

源码位置：SnipClone/AnnotationOverlay/AnnotationOverlay.cpp:61；同文件:368；SnipClone/PinWindow/PinWindow.cpp:69；同文件:428

问题：批注与贴图注册窗口类未设置 CS_DBLCLKS，却处理 WM_LBUTTONDBLCLK；标准双击不会按预期触发文字重编或关闭贴图。

复现/核验：分别双击文字和贴图，核对实际事件；标准系统消息要求 CS_DBLCLKS，已有处理器本身不等于功能可用。

改正方案：启用双击类样式；同时处理双击前的第一次单击，避免意外移动选区或创建图形。统一双击、Enter、Esc 的动作契约。

验收：文字在任意工具下双击重编；贴图双击按定义关闭；第一击不产生多余操作，输入法候选确认不误提交。

### A06 · P1 · 无工具状态下选区不能移动

视角：交互；证据：静态确认。

源码位置：SnipClone/FloatingToolbar/Toolbar.cpp:362；SnipClone/AnnotationOverlay/AnnotationOverlay.cpp:297；SnipClone/AnnotationOverlay/DrawStack.cpp:473

问题：再次点击工具会取消到 None；宿主仅在 Select 时把空白拖动转为选区移动，而 DrawStack 在 None 时直接返回。产品所需的无工具拖动行为未闭合。

复现/核验：选画笔→再次点击画笔关闭工具→在选区空白拖动，代码路径不移动选区也不画图。

改正方案：定义统一输入优先级：文字输入→选区手柄→已选对象手柄→对象命中→无工具/选择工具的空白移动→绘制。取消绘图工具后回到明确可用的选择状态。

验收：没有绘图工具时可移动选区；对象拖动与选区拖动可预期；光标显示当前操作，支持 Escape 取消当前手势。

### A07 · P1 · 批注阶段缺少完整冻结背景与外扩预览

视角：交互；证据：静态确认。

源码位置：SnipClone/AnnotationOverlay/AnnotationOverlay.cpp:71；同文件:959；同文件:1125

问题：框选结束换成选区大小窗口。外部区域恢复实时桌面；拖动外扩的边框画在原尺寸 DIB 上，超出部分被裁掉；批注阶段没有同样的左上尺寸标签。

验收：选择到批注不出现背景切换；向任意方向扩大都有实时边界、尺寸和底图预览；截图过程不把点击传到底层应用。

### A08 · P1 · 界面尺寸与多屏定位规则不统一

验收：三个缩放档下视觉尺寸一致、点击区域对齐；两栏不进入屏幕空隙或被任务栏覆盖；跨屏移动重新布局。

## 架构收敛方案

应用层保留一个AppController，统一管理热键、托盘、设置、当前截图会话和贴图服务。避免在main、批注和贴图之间维护不同设置副本。

截图会话拥有只读CaptureSnapshot、AnnotationDocument和视口。文档包含批注对象、选区和历史；批注坐标固定在冻结图空间。保持文档独立于HWND和键盘状态，将Shift约束等输入参数由宿主传入。

状态流：Idle → Selecting → Editing（选择/绘制/文字/调选区子状态）→ Exporting → Idle；取消当前手势回到Editing，取消截图回到Idle，导出失败回到Editing。文字编辑中的Enter/Esc先由IME决定，再由会话处理。

SceneRenderer复用D2D资源；UiChromeRenderer画遮罩、选区边框、手柄与尺寸标签。ExportService只合成文档，不带UI装饰。预览与导出共享绘制规则，使用不同的呈现资源。

冻结快照采用共享只读所有权，避免静态LastFreeze、全局宿主与局部复制共同维持多份大图。COM在明确线程边界初始化/反初始化；HDC、HBITMAP和COM对象逐步使用RAII，优先修复存在失败路径或所有权不清的模块。

先用文档快照修复一致性；有内存基准后再决定是否命令化历史。避免引入插件系统、微服务或大型UI框架。

## UI规格建议（待视觉验收）

- 基于用户提供的参考图：细蓝选区、白色圆形手柄带蓝边、左上尺寸标签、主栏右下对齐；保持整个编辑过程的冻结背景与区外遮罩。
- 主栏建议高度32–36 DIP、按钮30–32 DIP、图标16–18 DIP、图标线宽1.5–2 DIP、选区与主栏间距6–8 DIP；均为设计目标，不是当前实测值。
- 工具分组：选择｜图形下拉（矩形/椭圆）·箭头·画笔·马赛克·文字·橡皮｜撤销·重做｜取消·贴图·保存·复制。荧光笔等在基础验收后追加，不放不可用占位。
- 当前14个按钮主栏约528物理px宽，可折叠矩形/椭圆为图形组减少宽度；空间不足优先调整位置，必要时折叠次要工具，输出入口始终可见。
- 子面板跟随主栏，整体布局先算包围框，按当前显示器工作区下方/上方翻转；主栏不因切换工具跳动。
- 色板保留当前色与自定义色；线宽采用粗细示例＋当前值；文字采用字号、B/I、描边示例；马赛克显示块尺寸。
- 状态包括默认、悬停、按下、选中、禁用和键盘焦点；复制为主要完成动作，但仍保持轻量中性视觉。颜色、字体、间距、图标从统一设计参数读取。
- 自绘按钮提供名称、快捷键和可用状态，逐步补UI Automation和键盘导航。托盘使用独立产品图标，设置页统一中文文案。

## 产品契约与功能顺序

首先保证热键截图→框选调整→批注编辑→导出→贴图→关闭恢复的完整任务链。冻结编辑、可预测的撤销和不丢批注属于发布门槛。

贴图关闭历史应可消费、受内存上限约束；隐藏/显示与穿透为可见状态，退出穿透既有配置热键也有托盘入口。会话恢复与贴图再批注排在这些行为验证之后。

近期设置只包括热键、输出位置、常用样式和贴图基本行为。只有真正实现并验证后才显示开机启动等选项。

后续功能顺序：窗口自动识别→贴图再批注→荧光笔/模糊/编号→会话恢复。GraphicsCapture依据HDR、录屏、捕获质量或实测GDI缺陷评估，OCR/翻译/插件继续暂缓。
