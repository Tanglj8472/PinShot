# SnipClone：产品、UI 与新手体验评估及改进方案

评估日期：2026-10-12。代码基线：`cursor/snipclone-17f2` / `e07c5d8`。本文件是方案，不包含业务代码修改。

**判断：当前版本已经具备截图与标注的主要技术链路，但“修改已有内容”和“按自己的习惯配置软件”两条用户路径没有闭合。应将完整二次编辑与可视化设置作为下一版的核心交付。**

评估边界：本轮复查了输入处理、对象模型、样式修改、贴图保存和托盘设置的源码，并核查 Snipaste 官方资料。新手流程为认知走查，表达可预期的操作障碍；没有开展两款软件的并排桌面实测，也没有真实用户访谈、计时数据或当前版本逐像素视觉对照。此前该提交的 62 项逻辑断言与普通 smoke 通过，只证明所覆盖路径，不代表交互验收完成。

Snipaste 对标分为两层：普通版作为截图、入口、设置与基本操作参照；Pro 的直接二次编辑作为目标交互参照。官方功能表将 Re-edit、Free select 列为 Pro；旧基础操作文档仍存在通过撤销/重做重新编辑的说明，不能据此否认 Pro 的能力，也不能把 Pro 功能统称为免费版已有。[官方 Pro 说明](https://github.com/Snipaste/feedback/wiki/PRO) · [基础操作](https://github.com/Snipaste/feedback/wiki/Getting-Started)

## 1. 产品经理视角

### 1.1 用户要完成的工作

目标用户是需要快速说明问题的普通 Windows 用户：截取一个区域，画框和箭头，加几句文字，发现错误后直接修正，复制给别人；必要时贴在桌面继续查看或修改。推荐产品承诺：**截图之后随时改得动，常用设置找得到，失败之后回得来。**

当前已具备框选、画笔、矩形、椭圆、箭头、文字、马赛克、橡皮、选择工具、撤销重做、复制、PNG 保存及贴图。这些资产可以继续使用。产品成熟度的主要缺口在工作流衔接：

- **修改承诺不完整。** 能移动、删除对象，却不能通过统一属性面板修改既有矩形或箭头的颜色、粗细。文字有专用重编入口，导致不同对象的规则不一致。
- **贴图切断编辑连续性。** 截图编辑器保留对象，贴图却只收到合成后的图片。用户认为“把同一张图贴到桌面”，系统实际完成了不可逆的对象扁平化。
- **设置成本过高。** 常见热键配置被暴露为文件编辑任务。设置目录不等于设置界面；冲突提示没有就地解决入口。
- **恢复能力边界不清楚。** 最近关闭恢复是进程内有限数量的图片快照；缺少跨重启可编辑文档恢复。应在产品描述里区分这些能力。
- **开发验收与产品验收脱节。** 需要将“源码存在”“自动测试通过”“完整桌面任务通过”独立记录。现有 VERIFICATION 已做区分，发布决策也应遵循它。

Snipaste 官方将截图、标注、贴图作为相连的使用功能，并提供首选项、快捷键和细节解释；其 FAQ 建议新手先关注自启动与全局热键，其余沿用默认值。这是值得借鉴的渐进式设置方式。[官方网站](https://www.snipaste.com/) · [官方 FAQ](https://www.snipaste.com/faq.html)

### 1.2 优先级决策

下一版优先兑现“可靠修改”和“无需改配置文件”。荧光笔、编号、模糊、OCR、长截图、复杂旋转和图层管理留在后续需求池。新增工具的收益低于修复现有对象改不动的问题。

首批产品门槛：同一编辑会话内完整二次编辑、图形化基本设置、冲突可恢复。随后完成贴图继续编辑，才能宣称“截图—标注—贴图”编辑闭环。重启后继续编辑属于后续文档持久化能力，必须单独验收。

## 2. 二次编辑差距：不能只写成“支持选择”

二次编辑至少分为三个层次：当前截图中修改已有对象；贴到桌面后继续修改对象；保存工作后重启继续修改。SnipClone 当前只有第一层的一部分，后二层没有完整链路。第三层是建议建设能力，本报告不声称所有 Snipaste 版本都支持任意导出图片的对象恢复。

### E01：对象属性没有成为编辑目标【代码确认 / 最高优先级】

`DrawStack::ActiveStyle()` 在 Select 模式返回空；`AdjustWidth()` 改工具预设和正在绘制的对象；`SetColorRgb()` 改多种工具的默认颜色和 live 对象，没有修改已提交的选中图形。选择模式下 StylePanel 显示提示文字，不展示被选对象的属性。用户会遇到“框已经选中，颜色/线宽却改不到它”的断层。

证据：[DrawStack.cpp:86](../AnnotationOverlay/DrawStack.cpp)、[DrawStack.cpp:660](../AnnotationOverlay/DrawStack.cpp)、[DrawStack.cpp:708](../AnnotationOverlay/DrawStack.cpp)、[StylePanel.cpp:119](../FloatingToolbar/StylePanel.cpp)。

### E02：选择、绘制与调整的规则分裂【代码确认 / 最高优先级】

对象移动和缩放主要依赖 Select 分支；绘图工具下按下鼠标会开始新图形。新建完成虽然记录了选中索引，但不等于当前工具下能自然拖动它。切回绘图工具又会清除选择。矩形、椭圆、箭头、马赛克只支持两个端点手柄；文字与自由画笔没有同样的缩放控制。

马赛克还有命中几何问题：绘制区域是矩形，但命中分支把两个点作为折线计算距离，远离对角线的位置可能选不中。预期效果需要桌面补验，但几何不一致在代码中可确认。

证据：[DrawStack.cpp:49](../AnnotationOverlay/DrawStack.cpp)、[DrawStack.cpp:231](../AnnotationOverlay/DrawStack.cpp)、[DrawStack.cpp:293](../AnnotationOverlay/DrawStack.cpp)、[DrawStack.cpp:482](../AnnotationOverlay/DrawStack.cpp)。

### E03：文字可重编，但不能代表所有对象都可重编【代码确认 / 最高优先级】

双击文字可进入编辑；提交时 UpdateText 能带回样式，这是已有基础。统一选中态、字号/颜色/粗体的实时反馈、中文输入法、第一次单击是否产生副作用仍需桌面验收。文字在“编辑文字”与“选中对象”两种状态下的属性操作应保持一致。

证据：[AnnotationOverlay.cpp:170](../AnnotationOverlay/AnnotationOverlay.cpp)、[AnnotationOverlay.cpp:375](../AnnotationOverlay/AnnotationOverlay.cpp)。

### E04：贴图不是可编辑文档【代码确认 / 下一里程碑必交付】

DoPin 调用 ComposeExport，然后把 CaptureResult 交给 PinManager；PinSnapshot 只存图片、位置、缩放、透明度。贴图右键菜单没有继续编辑入口，也没有原始标注列表。因此不能通过增加一个“编辑”按钮恢复已经丢掉的对象。

证据：[AnnotationOverlay.cpp:745](../AnnotationOverlay/AnnotationOverlay.cpp)、[PinWindow.h:16](../PinWindow/PinWindow.h)、[PinWindow.cpp:238](../PinWindow/PinWindow.cpp)。

Snipaste Pro 官方明确描述选中同类已绘制对象再编辑，并提供克隆、删除等操作。我们的目标应是把选择、属性、几何调整、撤销组成同一套规则，而不是只对齐按钮数量。[Pro 二次编辑说明](https://github.com/Snipaste/feedback/wiki/PRO#annotate)

## 3. UI 设计师视角

本节评价当前布局代码与交互呈现，不冒充两款当前运行界面的像素级评测。此前提供的选区与底部工具栏图片可以作为构图方向，不能代表全部当前状态。

### 3.1 主要差距

- **层级不够明确。** 主工具栏已有绘制、撤销、输出分组及悬停提示，这是进步；但属性区没有表达“正在修改谁”，选中对象时反而显示英文操作提示。应该让上下文决定属性，而不是只让当前工具决定属性。
- **密度不稳定。** 属性区所有 None action 项统一占 180 像素，连单个线宽/字号读数也如此。数字读数应采用紧凑数值控件，解释文字放到提示区。
- **缩放规则不统一。** 主工具栏使用 DIP 与目标屏幕 DPI，StylePanel 的按钮 30px、间距 6px、色块 16px 仍固定。混合 DPI 下的最终效果待实测，但布局体系已不一致。
- **语义有误导。** 马赛克调节实际改变 mosaicSize，当前通用读数却取 width。属性应明确命名为“颗粒大小”，不能继续以线宽解释。
- **状态区分不足。** 截图范围、对象选中范围、文字输入范围需要不同手柄和轮廓规则；用户应一眼知道拖动后改变的是截图还是标注。
- **产品外观缺少整体规范。** 自绘工具栏、属性面板、系统色彩对话框、提示框、托盘需要统一语言、字体与动作命名。系统原生对话框可以保留，无须全部重写；关键是入口和状态一致。

证据：[Toolbar.cpp:214](../FloatingToolbar/Toolbar.cpp)、[Toolbar.cpp:284](../FloatingToolbar/Toolbar.cpp)、[StylePanel.cpp:23](../FloatingToolbar/StylePanel.cpp)、[StylePanel.cpp:193](../FloatingToolbar/StylePanel.cpp)、[StylePanel.cpp:257](../FloatingToolbar/StylePanel.cpp)。

### 3.2 建议的视觉与布局规范

以下尺寸是设计起点，需样机与桌面验证，不是 Snipaste 实测尺寸。

1. 主工具栏采用 32–36 DIP 点击区域、18–20 DIP 图标、8 DIP 外边距、4 DIP 常规间距。统一图标描边与光学居中；分隔绘制、撤销、输出三组。
2. 属性条跟随主工具栏，显示“矩形 · 已选中”或“矩形 · 新建样式”。数值输入宽度约 48–64 DIP；色块视觉尺寸 16–20 DIP，但点击目标至少 28–32 DIP。数字带单位；马赛克显示颗粒大小。
3. 主操作“复制”给出更强识别，保存与贴图并列次级动作；取消与输出分组分开。保持主栏位置稳定，更多功能进入溢出菜单。
4. 小选区、窄工作区、贴边、输入法候选窗口需要联合避让；属性条过宽时折行或收纳，不能仅 clamp 主工具栏。位置优先下方，再上方，再工作区内可用位置。
5. 选区边框、对象边框使用不同线型与手柄形状，避免仅靠颜色区分。文字编辑强调插入光标，其他装饰退后。常驻一行简短提示，如“拖动调整 · 双击修改文字 · Del 删除”。
6. 定义正常、悬停、按下、选中、禁用、键盘焦点六种状态；所有操作有中文名称及快捷键提示，属性控件也有提示和键盘焦点。
7. 第一阶段统一明亮主题并跟随系统字号/DPI；深色与高对比适配进入下一阶段。界面字体、字号与截图中文字标注字号是两套不同设置。

Snipaste 官网列出界面字体、主题色、快捷键与详细选项等定制能力；可借鉴其可配置思路，SnipClone 应保留自己的图标与视觉规范。[官方功能介绍](https://www.snipaste.com/)

## 4. 小白用户认知走查

角色：普通办公用户，不读 README，不认识 INI，也不记快捷键。以下是按代码与官方说明推演的场景，不是已完成的真人可用性测试。

### 场景 A：第一次打开，要知道软件在哪

用户先点击托盘图标。Snipaste 官方基础流程说明支持左键点击启动截图；SnipClone 当前处理双击截图与右键菜单，单击没有同样动作。可能误以为未启动。建议首次显示一次简短引导，提供“开始截图”“设置”；托盘单击截图，右键菜单，避免为必要功能要求猜双击。[基础操作](https://github.com/Snipaste/feedback/wiki/Getting-Started) · [TrayIcon.cpp](../Common/TrayIcon.cpp)

### 场景 B：画了红框，想改蓝色并加粗

预期：点框 → 属性显示它的颜色和线宽 → 修改 → 原框立即变化。当前：选择入口能找到框，但属性面板没有接管选中对象；切工具改参数又主要影响下一次绘制。用户可能反复点色块，最后撤销重画。这里是完整性问题，换皮不能解决。

### 场景 C：箭头挡住文字，想移动并调整端点

当前必须理解选择工具与绘制工具的不同分支。预期：新建对象自动选中，端点可见，拖主体移动、拖端点调方向；调整一次对应一次撤销。选区移动必须与对象移动清楚区分，不能点空白想取消选择却误改截图范围。

### 场景 D：输入错字，想改字、字号和颜色

当前有双击文字重编基础，应保留。目标：双击直接定位文字，已有样式同步到属性条；中文候选确认不会误完成；Esc 只取消本次文字修改并保留旧文本。字号输入、加减和预览一致，文字删除也能撤销。

### 场景 E：贴到桌面之后才发现箭头错了

用户会找右键“编辑”或尝试双击。当前贴图没有文档，也没有继续编辑菜单；双击行为是关闭，更容易与文字编辑习惯冲突。建议右键第一组加入“编辑标注…”，Space 进入编辑，双击默认也进入编辑，关闭由显式按钮或菜单承担。需要先保存对象数据；PNG 导入只可新增标注，不承诺自动识别原有箭头。[Snipaste FAQ：贴图 Space 进入标注](https://www.snipaste.com/faq.html)

### 场景 F：快捷键冲突，要换成习惯的按键

当前弹窗要求编辑 `%APPDATA%/SnipClone/settings.ini` 并重启。小白需要找目录、选编辑器、理解键值，且可能填错。目标：冲突提示直接打开设置中的对应项，按一下新组合就完成录制与校验；失败保留原有可用配置，托盘截图入口始终可用。

### 场景 G：修改保存位置、开机启动

现有设置模型能存热键、输出目录、自启动布尔值；源码检索中自启动字段仅被加载/保存，未见系统注册执行，不能只添加复选框就宣告支持。目标：目录浏览按钮、当前路径、打开目录；自启动由实际 OS 注册结果决定开关状态；失败明确显示原因。默认设置可以完成正常工作。

### 场景 H：按错 Esc 或关闭贴图后想恢复

当前非文字输入状态下 Esc 直接请求关闭；最近关闭只恢复图片。目标分级退出：先取消当前手势，再取消对象选择/绘图模式，最后退出截图；退出前在内存保留最近编辑文档供恢复。关闭贴图保留可编辑文档；恢复失败不得消耗唯一恢复记录。具体规则在帮助中可见，跨对象类型一致。

## 5. 改进方案与实施边界

### M1：当前截图内的完整二次编辑 + 基本设置【发布门槛 / P0】

**对象编辑统一契约：**

- 选择工具可选全部可编辑标注；新建结束自动选中当前对象，工具预设与选中对象分开存储。
- 属性面板绑定“编辑目标”：有选中对象时改对象；没有对象时改下一次绘制的预设。标签明确显示当前作用范围。切工具时显式清除选择，进入该工具的新建状态。
- 已选对象的主体/手柄优先接收移动与调整；空白单击清除选择，空白拖动行为由当前工具确定。截图范围移动优先使用边框或 Space+拖动，避免与对象取消选择混淆。
- 矩形/椭圆/马赛克用边与角手柄；箭头用端点；文字支持移动、内容和样式编辑，文字缩放手柄后续补齐。自由画笔先支持选择、移动、样式、删除，不把整体旋转与路径节点编辑塞入首批。
- 更新颜色、线宽、填充、字号与文本样式后即时显示，可撤销。一次拖动或连续数值调节合并成一个历史事务，取消恢复起始状态。
- Del 删除；对象复制使用 Ctrl+D 等明确动作，避免占用已有 Ctrl+C 的整图复制语义。复制/删除也提供对象右键菜单；多选、层级管理后续扩展。
- 文字输入拥有自己的 Esc/Enter/IME 处理优先级。主窗口 Esc 分级退出，不能直接吞掉全部工作。

**设置最小版本：**

- 托盘“设置…”为主入口；工具栏“更多 → 设置…”为补充入口；快捷键冲突通知直达“快捷键”页。
- 左侧先提供“常规、快捷键、截图与标注、输出、关于”。后续加入“贴图”，按能力分阶段开放，避免展示无效选项。
- 常规：自启动、首次引导/操作提示；开关必须绑定真实行为。快捷键：截图、显示/隐藏贴图、退出穿透；按键录制、冲突提示、恢复默认。
- 截图与标注：默认工具、记住上次样式、标注完成后的选择行为。输出：保存目录、命名规则、复制/保存后的动作。首批保持 PNG，其他格式随真实能力扩展。
- 采用“确定 / 取消 / 应用”，一致地管理设置草稿。应用成功后立即生效；失败保留旧值和原可用热键，不要求用户重启完成普通配置。
- 用户文案如“此快捷键暂不可用，请换一组按键”；无法确定占用进程时不虚构进程名称。设置文件保留为内部存储及高级入口。

M1 验收：已有红框可改蓝/加粗且不新建对象；同样操作适用于箭头；文字重编样式一致；马赛克整个显示区域可正确命中；改动均能撤销；不打开文件即可更改热键和输出目录；修改失败可回退。

### M2：贴图继续编辑与 UI 一致性【P1，依赖 M1 的编辑目标模型】

引入最小 Document：原始图像、裁剪视口、标注对象、编辑历史或必要快照。贴图持有文档和渲染缓存，编辑器接收文档；屏幕位置、缩放、透明度属于贴图视图状态。导出时才生成最终位图，输出失败保留文档。关闭/恢复沿用同一文档，不将合成图当唯一数据源。

保留目前 Direct2D/DirectWrite 和可用的快照撤销结构，增加明确的对象样式修改入口与稳定对象标识；不因这次产品调整更换渲染框架。图像像素可共享，避免每个历史记录重复拷贝整张冻结桌面。首阶段允许内部坐标兼容现状，但对外统一变换接口，避免随窗口迁移散落重映射逻辑。

统一工具栏、属性面板、文字编辑器的 DPI 与尺寸规范；补全状态、中文提示、数值控件和窄屏布局。持续冻结背景/外部遮罩恢复为稳定编辑环境；不同屏幕之间的光标命中与实际对象尺寸必须一起验证。

M2 验收：截图 → 画箭头和文字 → 贴图 → 再编辑原箭头和文字 → 关闭 → 恢复 → 继续编辑；100%、150%、200% 及混合 DPI 下属性栏可达且命中正确；不把这项验收扩大解释为重启恢复。

### M3：可恢复工作与效率增强【P2】

加入显式“保存可编辑项目”及重启恢复；文档格式包含版本号、底图、裁剪和对象，普通 PNG/JPEG 仍是最终图片。定义容量上限、清理规则、损坏文件恢复以及历史开启/关闭。近期文档缩略图、编号、荧光笔、模糊、样式预设按真实需求排序；长截图与 OCR 单独评估。

磁盘持久化应说明是否保存裁剪外原图，以及清除历史的方式；用户只是导出最终图片时不应意外附带隐藏原图。这是文档格式的行为边界，不需要打断每次截图。

M3 验收：保存项目 → 重启 → 原对象可继续修改；打开普通图片只可新增标注，界面明确说明差别；清除记录后不再出现在恢复列表。

### 并行稳定性修复【发布阻断项】

此前已确认的 smoke 在热键冲突时被模态弹窗阻塞，应与设置冲突处理一并修复；贴图恢复失败先消耗历史的路径需改为成功后提交或完整回滚。发布前完成绘制失败、输出失败、中文输入法及真实桌面任务验收。自动测试不能替代上述产品验收。

## 6. 如何证明新版本确实更好用

下一轮邀请 5 名未用过 SnipClone 的普通 Windows 用户，使用相同素材完成六个任务：首次截图；修改已有框颜色/粗细；修改文字；贴图后修改箭头；更改热键与目录；恢复误关闭内容。对照 Snipaste 时记录具体版本与免费/Pro，二次编辑任务采用支持该功能的 Pro；交替安排软件顺序以减少学习影响。

记录：是否无需提示完成、耗时、误操作/撤销次数、是否被迫重画、是否打开配置文件、任务后主观信心。下面是建议验收目标，并非测量结果：

- 至少 4/5 用户独立完成每个核心任务，首个截图复制任务在 60 秒内完成。
- 修改已有框颜色/线宽不需要重画；发现编辑入口后在 15 秒内完成。
- 5/5 用户可从托盘找到设置；配置热键和目录的任务无需打开 INI、无需重启。

- DPI 验收覆盖单屏 100/150/200%、双屏混合缩放及负坐标；测试实际点击、输入法候选框避让与工具栏可达性，不只截图比较。

本轮不提供“达到 Snipaste 的百分之多少”或未经测量的体验评分。M1 完成代表当前会话可修改且基本可配置；M2 完成代表贴图编辑闭环；M3 完成才代表跨会话继续工作。
