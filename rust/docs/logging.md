# 系统日志

在设置的「通用 → 系统日志」选择日志等级，保存后应用到主程序。

| 设置 | 写入内容 |
| --- | --- |
| 关闭 | 不写入日志记录 |
| 普通 | 普通事件 `[I]` 和错误 `[E]` |
| 追踪 | 普通内容及耗时等追踪信息 `[追踪]` |
| 调试 | 以上内容及调试信息 `[D]`，包括内存快照 |

`--debug` 或非空且不为 `0` 的 `PINSHOT_DEBUG` 会覆盖配置，启用调试级别和控制台输出。
旧配置的 `detailed` 等价于 `trace`，未知值回退到 `normal`。

日志保存在应用的 `data_dir()` 下，文件名为 `pinshot.log`。
Windows 默认位置为 `%APPDATA%\PinShot\pinshot.log`。
格式为 `[YYYY-MM-DD HH:MM:SS.mmm UTC] [等级] [pid=进程号] [源文件:行号] 内容`。
追踪等级直接显示为 `[追踪]`；普通、错误、调试分别保持 `[I]`、`[E]`、`[D]`。
时间使用 UTC；与本地操作时间对照时需要换算时区。

每次写入前检查大小，超过 10 MiB 时轮换到 `pinshot.log.1`，保留一份备份。
文件写入由后台线程执行，界面线程使用最多 256 条记录的队列；队列满时丢弃新增记录并在后续写入中记录丢弃数量。
每条格式化记录最多 64 KiB，超出部分标记为截断。退出和异常处理最多等待两秒完成队列刷新。
`pinshot.log.lock` 用于协调主程序、设置窗口和安装辅助进程；写入者持锁期间完成轮换和写入，写入后关闭数据文件。
请一并提供当前日志和备份，以便分析跨轮换的操作。

翻译日志记录请求结果、字符数、服务商和耗时，不记录原文、译文或服务商错误响应正文。
启动记录不包含命令行参数原文。诊断截图仅由独立的显式截图转储选项触发，调试日志等级不会自动启用它。

开发时：正常事件使用 `logutil::log`，错误使用 `logutil::error`，耗时使用 `logutil::ms`。
高频诊断应显式调用 `logutil::log_at("trace", ...)` 或 `logutil::log_at("debug", ...)`。
不要把配置结构、API 密钥、请求正文或剪贴板文本作为日志内容。
