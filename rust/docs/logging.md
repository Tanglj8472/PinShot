# 日志与诊断

在设置的“常规 → 系统日志”选择等级。日志用于定位启动、捕获、安装、OCR 和翻译等问题，不自动保存屏幕画面。

## 日志等级

| 等级 | 写入内容 |
| --- | --- |
| 关闭 | 不写入日志记录 |
| 普通 | 普通事件 `[I]` 和错误 `[E]` |
| 追踪 | 普通内容及耗时信息 `[追踪]` |
| 调试 | 以上内容和调试信息 `[D]`，包括内存快照 |

`--debug` 或非空且不为 `0` 的 `PINSHOT_DEBUG` 会启用调试级别，并输出到控制台。旧配置的 `detailed` 等价于 `trace`，未知等级回退到 `normal`。

## 位置与格式

Windows 默认数据目录为 `%APPDATA%\PinShot`，可由 `PINSHOT_DATA_DIR` 覆盖。文件按记录的 UTC 日期命名：

```text
pinshot-YYYY-MM-DD.txt
pinshot-YYYY-MM-DD.txt.1
```

记录包含 UTC 毫秒时间、等级、进程号、源文件和行号。对照本地操作时间时要换算时区。`pinshot.lock` 用于多进程协调，不是用户日志。

## 写入与保留

文件写入由后台线程执行，队列最多 256 条；队列满时丢弃新增记录，后续写入丢弃数量。单条记录最多约 64 KiB，退出刷新最多等待两秒。

当当天日志超过约 10 MiB 时，轮换到同日期的 `.txt.1`，仅保留一份轮换备份。

当前清理逻辑在启动时清理超过两天的轮换备份；普通按日 TXT 文件尚未纳入同一自动清理逻辑。因此不能保证所有日志都只保留两天。这是现有实现限制，不应沿用旧文档的保证。

## 隐私与排障

翻译日志不应记录原文、译文、密钥或完整服务商错误正文；启动日志不记录原始命令行参数。截图转储必须由独立的显式选项触发，调试等级不会自动启用。

报告问题时提供应用版本、版本类型、Windows 内部版本、复现步骤及相关时间段的脱敏日志。不要直接上传配置、剪贴板内容或私人截图。

## 开发约定

使用 `logutil::log` 记录事件，`logutil::error` 记录错误，`logutil::ms` 记录耗时。高频诊断显式选择追踪或调试等级，不把配置结构、请求正文或凭据写入日志。
