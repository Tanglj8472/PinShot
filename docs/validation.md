# 验证记录与覆盖范围

验证结论必须绑定源码、构建和环境。当前构建状态以 [GitHub Actions](https://github.com/Tanglj8472/pinshot/actions) 对应提交为准，本页不替代实时检查。

## MCP 已有证据

2026-10-19 的本机测试验证了 Windows 原生捕获到 MCP 图片返回的链路：

| 场景 | 结果 |
| --- | --- |
| 全屏捕获 | 原图 4160 × 1400，返回可读取的缩略预览 |
| 单窗口捕获 | 窗口枚举、标题匹配及 PNG 返回成功 |
| 原生标注 | 方框、箭头、文字、椭圆可见；早期流程还覆盖模糊与马赛克 |
| 编辑撤销重做 | 窗口建立后新增标注，数量变化正确，ID 保持稳定 |
| 会话管理 | 显示、隐藏、再次显示和关闭成功 |
| 输出 | 预览及完整尺寸保存成功，重复保存被拒绝 |

早期原生会话构建对应提交 `6a3ac81`，可见预览对应 `40cb2e2`，随后 `6f84ca2` 的 Windows 构建通过。历史检查不证明任意后续提交仍然通过。

手工绘制、拖动、文字输入与 AI 的完整双向交互仍需专项验收。第三方 Windows-MCP 的点击测试不计入 PinShot 本身的 MCP 功能。

## 安装与运行

既有发布流程覆盖运行库审计、独立配置启动、运行中升级、关闭失败处理、自动更新参数及卸载数据保留。旧的 0.2.6 候选记录属于历史测试，不能用于证明当前 Lite 已兼容旧系统。

2026-10-26 的 Lite 检查已验证禁用模块、工具栏裁剪及不引入推理库；安装包构建结果应以最终对应 Actions 运行记录为准，不交付失败任务中的中间产物。
