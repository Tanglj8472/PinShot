# 性能实验与复现

本文保存历史实验结论，不作为当前版本在所有设备上的性能承诺。硬件、驱动、模型、图像及执行后端变化都会影响结果。

## 历史测量

早期 Windows 实验使用 16 GB 内存、Intel 核显与 NVIDIA RTX 3050，并存在虚拟显示器及远程工具。OCR 样本尺寸为 1686 × 729。

| 配置 | 模型加载后工作集 | 推理后工作集 | 推理后 Private | 耗时 |
| --- | --- | --- | --- | --- |
| Server + WebGPU | 约 629 MB | 约 1823 MB | 约 3018 MB | 约 15.9 秒 |
| Mobile + CPU | 约 418 MB | 约 648 MB | 约 678 MB | 约 6.6 秒 |

两组同时改变了模型和执行后端，不能据此认定所有 GPU 都比 CPU 慢。Mobile + WebGPU 在该实验环境出现过着色器错误，该失败不能推广到所有驱动或后续版本。

字符数接近不等于识别准确率相同。单张图和少量样本不能替代准确率评测。

## 内存解读

- 工作集表示驻留物理内存，Private 表示进程私有提交量，两者都是真实且有意义的指标。
- 工作集较低不能证明没有泄漏；Private 较高也不能仅凭数值断言由 GPU 预留造成。
- 驱动、映像和映射区域需要结合模块、虚拟内存区域及系统工具归因。
- OCR 峰值应在模型加载、检测、识别和释放阶段分别测量，不能只看结束后的值。
- 一份 4160 × 1400 的四通道图像约占 22.2 MiB；多份缓冲和多个贴图会增加占用。

历史实验里，降低检测长边上限可能减少耗时和内存，但也可能减少文本块、破坏布局。不能只根据耗时选择参数。

## 复现方法

在 `rust` 目录打开独立测试程序并采样：

```powershell
./target/release/pinshot.exe --debug
./tools/mem-probe.ps1 -Seconds 30
./tools/mem-modules.ps1
./tools/mem-regions.ps1
./tools/mem-compare.ps1
```

完整版 OCR 可用 `./tools/ocr-sweep.ps1` 进行对比。采样前阅读脚本参数，不在实际用户会话中强行结束进程或清空配置。

记录源码提交、版本类型、硬件、驱动、显示器、模型、后端、样本尺寸、工作集、Private、耗时与识别结果。先使用默认设置，再一次只改变一个变量。

## 保留结论

历史实验说明模型大小、输入尺寸和执行后端都值得分别测试，不应写死某一种硬件配置。部分实验优化最终回退，不能把实验分支的行为当作当前实现。Lite 不包含 OCR 或 MCP，应与完整版分别测量。
